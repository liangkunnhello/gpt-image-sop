## 15:35 追加：质检与相似度实测

### 工作流纠正（重要）
用户实际链路：**参考图 → 反推系统提示词 → 系统提示词生成生图 SOP → SOP 写多条提示词 → 一条提示词出一张图**。
不是"一条提示词出多张图"。故 `batch.csv` 的 `count` 默认 1；
相似度比较对象是**同批 SOP 展开的多张图两两之间**。

### 质检定稿
- 模型 `deepseek-v4.1-flash`。
- 关思考参数：`thinking:{type:"disabled"}` 实测 reasoning_tokens=0；`reasoning_effort:"none"` 同样有效；
  `enable_thinking:false`、`chat_template_kwargs` **无效**（照样思考）。
- 关思考收益：输出 token 568→185（成本降约 2/3）；耗时 32s→28s（大头是图片传输）。
- 缩量收益：2048px/3.9MB → 1400px/165KB，28s→4.3s，8 条文案仍全对。
- 服务端接受 `response_format:{type:"json_object"}`；仍偶发括号打错，已加扁平 schema + 括号平衡容错 + 重试一次。
- **致命坑（已修）**：expect 为空时曾静默降级成"不查文字"并判 pass，属假通过。现改为找不到标准答案直接报错退出。

### 相似度（CLIP ONNX）
- 模型 `Xenova/clip-vit-base-patch32` 量化版 89MB，经 hf-mirror 下到 `~/.gpt-image-cli/models/clip-vit-base-patch32/`。
- 机器无 torch/transformers，走 onnxruntime + numpy + PIL。
- 脚本 `tools/clip_similarity.py`。
- **jdb 16 张（模板海报）**：120 对，min 0.6935 / P10 0.7341 / mean 0.8163 / P90 0.8956 / max 0.9490；落 0.8–0.92 共 74 对（62%）。
- **sweet 10 张（人像多风格）**：45 对，min 0.4691 / P10 0.4965 / mean 0.6499 / P90 0.7603 / max 0.8246；落 0.8–0.92 仅 3 对。
- 结论：**0.8–0.92 只适合同模板批量（海报），不能套人像多风格**。阈值须按品类基线或批内相对分位。
- 撞车仅 2 对：01×15(0.949)、01×19(0.9202) → 只需重出 1 张。
- CLIP 对文字内容不敏感，看的是构图/版式/色调 → 降相似度要改 layout/scene/tone，改文案没用。

`src/batch/parse-prompts.mjs`、`src/batch/run.mjs`、`src/batch/qc.mjs`、`tools/clip_similarity.py`。
